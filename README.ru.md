# Инфраструктурный набор инструментов для MCP

![Демонстрация](screenshots/demo.svg)
[![CI](https://github.com/uMax-Cyber/MCPForge/actions/workflows/ci.yml/badge.svg)](https://github.com/uMax-Cyber/MCPForge/actions/workflows/ci.yml)

Архитектурные паттерны и системы безопасности для запуска серверов Model Context Protocol (MCP) поверх боевой инфраструктуры (файрволы, сетевые контроллеры, гипервизоры). Создано на основе реальных внедрений: 6 MCP-серверов, 312 инструментов, режим полного доступа с защитными ограничениями.

## Проблема

MCP-серверы дают ИИ-агентам прямой доступ к боевой инфраструктуре. Без структуры слабые LLM галлюцинируют параметры, смешивают данные из разных источников и не отличают ошибки от данных. Этот набор инструментов предоставляет паттерны, которые делают такой доступ безопасным.

## Ключевые паттерны

### 1. Паттерн маршрутизации инструментов (для больших каталогов)
Когда на сервере 200+ инструментов, не показывайте их все модели. Вместо этого:
```
route_tools(query="list VMs") → возвращает имена релевантных инструментов
call_routed_tool(name="list_vms", arguments={...})
```
Это сжимает 200 инструментов до 3 видимых, экономя контекстное окно.

### 2. Уровни безопасности (степени автономности)
```
🟢 ЗЕЛЁНЫЙ — чтение/списки/статусы: выполнять свободно
🟡 ЖЁЛТЫЙ — удаление/откат/изменение размера: сначала подтвердить с пользователем
🔴 КРАСНЫЙ — критическая инфраструктура (собственный хост агента): НИКОГДА
```

### 3. Двойная резервная память
Основной вариант: RAG-сервер (семантический поиск)
Резерв: файловое markdown-хранилище (поиск через grep)
Интерфейс: единый скрипт, работающий с обоими и всегда пишущий в оба.

### 4. Правила анти-галлюцинаций для MCP
- Данные — только из фактических результатов инструментов
- Ошибка ≠ данные (сообщить об ошибке, а не выдумывать правдоподобные числа)
- Усечённый вывод ≠ полные данные
- Не смешивать факты из разных VLAN/источников без проверки
- Результат инструмента > «знания» модели

## Архитектура

```
┌─────────────┐     ┌──────────────────┐     ┌─────────────────┐
│  ИИ-агент   │────▶│  MCP-серверы ×6  │────▶│  Инфраструктура │
│  (Hermes)   │◀────│  (312 инструментов)│◀────│  (Proxmox/UniFi/ │
└─────────────┘     └──────────────────┘     │   Sophos/LightRAG)│
                           │                 └─────────────────┘
                           ▼
                    ┌──────────────┐
                    │ Уровень      │
                    │ безопасности │
                    └──────────────┘
```

## Примеры конфигурации

- `config/mcp_servers.yaml` — конфигурация нескольких серверов с переменными окружения
- `config/safety_rules.yaml` — классификация действий по уровням
- `examples/routed_pattern.py` — последовательность вызовов маршрутизированных инструментов

## Реальные метрики

| Метрика | Значение |
|--------|-------|
| MCP-серверы | 6 (unifi, proxmox×3, sophos×2) |
| Всего инструментов | 312 |
| Инструментов на сервер (маршрутизация) | 3 видимых |
| Нарушения безопасности после обучения | 0/8 тестов |
| Уровень галлюцинаций после обучения | 0% (8/8 тестов пройдено) |
